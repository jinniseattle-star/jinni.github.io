How Modern Switches Revolutionized Networking (And Why My Hub Almost Saved—Then Ruined—Everything)

Alex Chen

Systems & Network Engineer

If you’ve ever looked behind your desk or TV stand, chances are you’ve seen a little box with a bunch of Ethernet ports pulsing with green and amber lights. To most people, any hardware box that accepts Ethernet cables is just "that internet splitter thing."

Earlier this week, I made the classic mistake of assuming all multi-port networking devices were created equal. I dusted off an old network hub I had lying around to connect a few devices in my home setup, expecting smooth, high-speed sailing. Instead, my network slowed to a crawl, latency spiked dramatically, and file transfers kept dropping.

That frustrating bottleneck kicked off a deep dive into fundamental networking architecture. Here is what I discovered about hubs vs. switches, the phenomenon known as collision domains, and why modern switches are one of the unsung heroes of the internet age.

01 The Hub Era: A Highway with No Lane Lines

To understand why my setup choked, you first have to understand how a network hub operates.

A hub is a Layer 1 (Physical Layer) device—essentially a multi-port electrical repeater. It has zero intelligence regarding which device is connected to which physical port. When Host A sends a packet meant specifically for Host B, the hub doesn't know where Host B is located. So, it does the only thing it can: it duplicates the electrical signal and broadcasts it out every single connected port.

Hub Architecture (Blind Broadcast) Shared Channel 
[ Host A ] --(Sends Packet)--> [   HUB   ] --(Broadcasts to ALL)--> [ Host B ] (Intended Receiver)
                                                                 [ Host C ] (Uninvolved)
                                                                 [ Host D ] (Uninvolved)

This simple design introduces two massive structural drawbacks:

Security & Overhead

Uninvolved devices constantly receive data traffic intended for someone else, wasting processing bandwidth and creating security risks.

Single Collision Domain

Because everyone shares the exact same physical communication channel, only one device can transmit at a time (half-duplex mode).

02 Learning About Collision Domains the Hard Way

A collision domain is a network segment where data packets sent by two or more devices can physically collide on the shared medium, causing data corruption.

When two devices connected to a hub attempt to talk at the exact same time:

  1. A data collision occurs on the physical wire.
  2. Both devices detect the voltage spike/signal interference.
  3. Both devices send out a jam signal, abort their transmission, and invoke a randomized backoff timer (CSMA/CD protocol) before trying again.
In a small network with minimal traffic, you might not notice the delay. But as soon as I started transferring large media files between multiple devices, collision after collision forced endless retries. My network performance plummeted—all because every device plugged into that hub was trapped inside one single, crowded collision domain.

03 The Evolutionary Bridge: Enter the Switch

To solve the collision nightmare, networking hardware evolved through multi-port bridges, which matured into modern Ethernet switches.

Unlike a hub, a switch operates at Layer 2 (Data Link Layer) and possesses hardware intelligence. It automatically builds an internal MAC Address Table by observing incoming traffic frames:

// Switch Internal MAC Address Table
Port 1 ==> AA:BB:CC:11:22:33 (Host A)
Port 2 ==> AA:BB:CC:44:55:66 (Host B)
Port 3 ==> (Unmapped)

When Host A sends data to Host B, the switch inspects the destination MAC address in the frame header and forwards the frame only to Port 2. Ports 3, 4, and 5 stay completely silent and open for other simultaneous conversations.

Switch Architecture (Targeted Forwarding) Micro-Segmented 
[ Host A ] --(Sends Data)--> [  SWITCH  ] --(Directly Forwards)--> [ Host B ]
                                 |
              (Ports C & D remain open for independent transfers!)

Micro-Segmentation & Full-Duplex Mode

By isolating traffic per port, a switch micro-segments the network. Every single port on a switch becomes its own independent collision domain. Additionally, because modern switches operate in full-duplex mode, devices can send and receive data at the exact same time without signal interference.

Mathematically, collisions are virtually eliminated, and overall network throughput scales exponentially.

04 Detailed Comparison: Network Hub vs. Switch

Here is a quick breakdown of how these two devices compare side-by-side:

Feature Network Hub Network Switch
OSI Layer Layer 1 (Physical) Layer 2 (Data Link) / Layer 3
Device Intelligence None (Blind Repeater) High (Learns MAC addresses per port)
Collision Domains 1 single domain shared across all ports 1 separate collision domain per port
Duplex Mode Half-Duplex (Send or Receive) Full-Duplex (Send and Receive simultaneously)
Performance Degrades under heavy traffic High-speed, isolated traffic flow

Conclusion & Next Steps

Switches fundamentally changed local area networks by moving us away from noisy, shared broadcast channels to dedicated, point-to-point connections. Replacing my old hub with a basic Gigabit switch instantly brought my network back to life, eliminating the artificial bottleneck I had accidentally created.
